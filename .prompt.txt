## Critical Issues

### 1. Memory Leak - Event Listeners Not Cleaned Up
**File:** `src/lib/gameEngine.ts:8165-8188`

The `setupInputHandlers()` method adds event listeners to the `window` object, but these are never removed. When the component unmounts and `engine.stop()` is called, only the animation frame is cancelled—the event listeners remain attached.

**Impact:** Memory leak when component remounts, multiple listeners accumulating

**Fix:** Add cleanup in the `stop()` method:
```typescript
private keydownHandler = (e: KeyboardEvent) => { /* ... */ };
private keyupHandler = (e: KeyboardEvent) => { /* ... */ };

private setupInputHandlers() {
  window.addEventListener('keydown', this.keydownHandler);
  window.addEventListener('keyup', this.keyupHandler);
}

stop() {
  if (this.animationFrameId !== null) {
    cancelAnimationFrame(this.animationFrameId);
    this.animationFrameId = null;
  }
  window.removeEventListener('keydown', this.keydownHandler);
  window.removeEventListener('keyup', this.keyupHandler);
}
```

### 2. No Frame Time Delta - Variable Game Speed
**File:** `src/lib/physics.ts:8235-8242`, `src/lib/gameEngine.ts:8201-8211`

The physics update doesn't account for variable frame times. On slower devices or when tab is backgrounded, the game will run at different speeds. All velocity/gravity values assume 60fps.

**Impact:** Inconsistent gameplay across devices, potential fast-forwarding when tab regains focus

**Fix:** Pass delta time to physics update:
```typescript
private lastFrameTime = performance.now();

private gameLoop = () => {
  const currentTime = performance.now();
  const deltaTime = (currentTime - this.lastFrameTime) / 16.67; // Normalize to 60fps
  this.lastFrameTime = currentTime;
  
  this.physics.update(this.state, { ... }, deltaTime);
  // ...
};
```

Then multiply all velocity/position changes by `deltaTime` in physics.

## Major Issues

### 3. Camera Positioning Not Responsive
**File:** `src/lib/physics.ts:8313-8318`

The camera offset is hardcoded to `player.position.x - 300`, which doesn't account for the actual canvas width. On narrow screens, the player will be off-center or even off-screen.

**Fix:**
```typescript
private updateCamera(camera: Vec2, player: Player, canvasWidth: number) {
  const targetX = player.position.x - canvasWidth / 2;
  camera.x = Math.max(0, targetX);
}
```

Pass `canvasWidth` through the update chain.

### 4. No Player Boundary Checking
**File:** `src/lib/physics.ts:8244-8262`

The player can move left beyond x=0 and can fall indefinitely below the screen. There's no death/respawn mechanic or boundary enforcement.

**Fix:** Add boundary checks:
```typescript
private updatePlayer(player: Player, input: { ... }, worldWidth: number) {
  // ... existing movement code ...
  
  // Clamp player position
  player.position.x = Math.max(0, Math.min(player.position.x, worldWidth - player.width));
  
  // Respawn if fell off screen
  if (player.position.y > 700) {
    player.position = { x: 100, y: 400 };
    player.velocity = { x: 0, y: 0 };
  }
}
```

### 5. Space Key Dual Behavior Is Confusing
**File:** `src/lib/gameEngine.ts:8169-8177`

The space key both starts the game AND makes the player jump, but on first press it only starts—you can't jump immediately. This creates a poor UX where the player must press space twice to actually start playing.

**Fix:** Start the game automatically when the component mounts, or use a separate key (Enter) to start:
```typescript
if (e.key === ' ') {
  e.preventDefault();
  this.input.jump = true;
}
if (e.key === 'Enter' && !this.state.isPlaying) {
  this.state.isPlaying = true;
}
```
