### 1. Jump Input Not Being Consumed (Game.tsx:61-63)

**Location**: `src/components/Game.tsx:61-63`

**Issue**: The jump input consumption logic has a critical flaw:

```typescript
if (input.jump && player.isGrounded) {
  inputController.consumeJump();
}
```

This check happens AFTER `updatePlayer()` executes. When a jump is successfully applied in the engine (line 34-37 of GameEngine.ts), `isGrounded` is immediately set to `false`. This means:

1. Player lands while holding space
2. `updatePlayer()` sees `input.jump && isGrounded` → applies jump and sets `isGrounded = false`
3. Line 61 checks `input.jump && player.isGrounded` → but `isGrounded` is now `false`!
4. `consumeJump()` is NEVER called
5. The jump input persists, causing the player to jump again on the next landing

**Impact**: Player will continuously jump on every landing while holding the space bar, despite the `jumpPressed` flag attempting to prevent this.

**Fix**: Capture grounded state before the update, or unconditionally consume jump input:

```typescript
// Option 1: Check previous state
const wasGrounded = player.isGrounded;
player = gameEngine.updatePlayer(player, input, platforms, CANVAS_WIDTH, deltaTime);
if (input.jump && wasGrounded) {
  inputController.consumeJump();
}

// Option 2: Always consume (simpler)
player = gameEngine.updatePlayer(player, input, platforms, CANVAS_WIDTH, deltaTime);
if (input.jump) {
  inputController.consumeJump();
}
```

## Minor Issues ⚠️

### 2. Collision Resolution Priority (GameEngine.ts:84, 94, 103, 112)

The code uses `break` statements after resolving each collision, processing only the first platform that collides with the player. In scenarios where the player collides with multiple platforms simultaneously (e.g., landing in a corner), the order of platform iteration determines which collision is resolved. This could lead to unexpected behavior in edge cases.

**Recommendation**: This may be acceptable for a simple platformer, but consider tracking the "best" collision to resolve (e.g., the one with smallest overlap or most relevant to player velocity direction).

### 3. Delta Time Capping (Game.tsx:53)

## Critical Bugs Found 🐛

### 1. Variable Jump Height Applied Every Frame
**Location**: `src/lib/GameEngine.ts:89-91`

```typescript
if (input.jumpReleased && updated.velocity.y < 0) {
  updated.velocity.y *= this.VARIABLE_JUMP_CUT;
}
```

**Problem**: The `jumpReleased` flag remains `true` from when the jump key is released until it's pressed again. This causes the velocity to be cut by 50% **every frame** after release, not just once.

**Result**: 
- Frame 1 after release: velocity × 0.5 = 50%
- Frame 2 after release: velocity × 0.5 = 25%
- Frame 3 after release: velocity × 0.5 = 12.5%
- Player falls almost immediately after releasing jump

**Fix**: Either consume the `jumpReleased` flag after applying the cut, or track whether the cut has already been applied for the current jump:

```typescript
// Option 1: Add jumpCutApplied tracking to Player type
if (input.jumpReleased && updated.velocity.y < 0 && !updated.jumpCutApplied) {
  updated.velocity.y *= this.VARIABLE_JUMP_CUT;
  updated.jumpCutApplied = true;
}
// Reset jumpCutApplied when starting a new jump

// Option 2: Make jumpReleased consumable like jump
```

### 2. Coyote Time Jump Not Consumed
**Location**: `src/components/Game.tsx:72-76`

```typescript
const wasGrounded = player.isGrounded;
player = gameEngine.updatePlayer(...);

if (input.jump && wasGrounded) {
  inputController.consumeJump();
}
```

**Problem**: When jumping during coyote time (after walking off a platform), `wasGrounded` is `false`, so the jump input is never consumed. If the player lands quickly, they'll jump again immediately without releasing the key.

**Scenario**:
1. Player walks off platform → `isGrounded = false`, coyote time active
2. Player presses jump → GameEngine applies jump (valid coyote time jump)
3. `wasGrounded` is `false`, so jump isn't consumed
4. Player lands quickly → `isGrounded = true`, `input.jump` still `true`
5. Player immediately jumps again without releasing key

**Fix**: GameEngine should return whether a jump was actually performed, or the consumption logic needs to handle all jump cases:

```typescript
const jumpResult = gameEngine.updatePlayer(...);

if (jumpResult.jumpPerformed) {
  inputController.consumeJump();
}
```

## Minor Issues

### 3. Crouch Collision Box Doesn't Match Visual
**Location**: `src/components/Game.tsx:96-99`

The visual height changes when crouching (60% of normal height), but the actual collision box in `player.height` remains unchanged. This creates a mismatch between what the player sees and the actual collision detection.

**Suggestion**: Consider shrinking the collision box when crouching, or document this as intentional design (some platformers do this intentionally).
